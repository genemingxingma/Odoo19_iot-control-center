- 使用合成数据，没有复制患者、生产考勤或其他生产业务记录。禁用测试进程的 cron 和真实设备下发配置。

升级演练先安装 V1 并建立监测原始行、小时汇总行、合成员工与考勤。未开启授权开关时，V2 升级失败且两条旧监测记录仍在；通过 ORM 开启测试授权后，升级成功，旧温湿度历史被清空，员工、考勤、联系人、网关和探头名称仍在。

随后通过真正的新事务入库服务发送事件、重发事件、使用同一事件编号修改内容：最终只有一条原始记录和一条事件回执，修改内容的重放被拒绝。

本轮迁移保护通过临时旧版结构表补测：缺少清理授权、重复网关编号、网关无公司和跨公司探头都会在删除历史前停止；两条旧记录、一条告警和探头启用状态均保留。合法身份可通过检查。不再把公司归属有问题的具名探头自动归档。

故障注入发现并修复了三个队列问题：非法事件编号导致整批读取退出、持续重试的前一批数据阻塞后面的网关、Tokio 异步写入失败未在 `sync_all` 前检查导致空文件被当作成功持久化。最后一项由真实 ENOSPC 测试复现，修复后重新完成整组故障注入；Linux `/dev/full` 回归也覆盖了此错误。300 个已保存事件在强制重启和错误回执后保持原编号与内容，恢复后全部确认。

证据位于服务器隔离目录的 `followup-test.log`、`concurrency-test.log` 与 `concurrency-console.log`；可复用脚本是 `tools/test_bridge_faults.py` 和 `tools/test_v2_ingest_concurrency.py`。并发测试无序列化冲突或死锁，但启动日志有一条独立的 Enterprise social 模块状态不一致提示，因此不能声称整个隔离环境的日志完全无错误。上述固定规模测试也不是长时间容量测试。

Linux 候选产物在本地 `deploy/artifacts/iot_bridge-linux-amd64`（不提交二进制）；SHA-256：`8c82270ae49dcfc7e1c922f03bd838a1bbcd304b172f83b98ae2a7d45065b066`。

网页验收使用两个具名探头、每个探头 24 个小时采样的合成数据。已检查列表与图例的名称及编号、小时图与原始记录的时区一致性。现场发现服务器默认小时标签可能使用无上午/下午标记的 12 小时制，导致图表按标签合并不同时段；候选已改为日期、24 小时制和 UTC 偏移的明确标签。

双指标图的左右纵轴与原始数值已核对。指标菜单只保留温度和相对湿度，极值及样本数保留在透视统计中；没有把不同单位相加或用温湿度占比制作饼图。

## 发布前仍需完成

- 每种真实继电器硬件型号的 GPIO 极性、断电重启、倒计时到期、手动关闭、重放、看门狗和网络切换测试。编译通过不能替代电气状态验证，紫外设备仍需物理联锁。
- 更长时间、完整 Odoo HTTP 链路和实际设备速率下的容量测试。现有故障注入使用模拟 HTTP 回执，不能代替生产全链路吞吐验收，也不保证断线前尚未持久化的 MQTT 数据不会丢失。
- 生产备份恢复演练、设备身份清单与公司归属审查、OTA 证书信任和 OpenWrt 主机密钥准备。
- 告警确认/处理工作流、带回差和持续时间的告警策略、自适应保峰降采样，以及更完整的队列容量/年龄诊断尚未实现，不能把本次核心架构验收等同于这些功能已完成。

本记录是候选验收证据，不是生产或全量固件发布批准。发布与回退步骤见 `UPGRADE_V2.md`。

## 本轮生产预检与决定

用户已允许在测试全部完成后更新 `imytestth`。本轮只做生产只读预检，没有满足条件的项目不会被当作已通过。

- 生产仍为 `19.0.1.0.19`；13 个继电器中 11 个为 1.8.10、2 个为 1.8.8，无 2.0.0。旧固件没有 V2 `delay_start`、命令到期和顺序防重放语义，不能只升级服务器。
- 50 条网关记录均未配置公司，网关编号存在 4 组重复。17 个探头中 16 个属于公司 1，并绑定当前同一网关；另一个探头 `B001-ch01` 未配置公司。不会通过猜测统一归属或删掉探头配置绕过迁移问题。
- 来源地址曾随公网 IP 改变而生成新网关，需要明确稳定的 WireGuard 来源映射后再切换，不把公司地址写死在固件中。
- 生产日志末尾 10000 行样本（2026-09-06 05:54 至 10:56 UTC）含 27 处序列化冲突文本。该样本不是 27 个独立故障的精确统计，也不能用候选并发测试通过来宣称生产冲突已修复。
- 备份恢复演练、每种硬件的实际断电/倒计时/关闭验证以及现场安全条件尚未完成。两台旧固件设备长期未上报，不能宣称可以全量在线 OTA。

决定：保留候选并推送重构分支，暂不切换生产。`odoo`、`iot-bridge`、`iot-ota-proxy` 均为 active；本轮没有重启这些生产服务，也没有替换生产代码、中间件或设备固件。
