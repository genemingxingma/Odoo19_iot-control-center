# 继电器 2.0.1 试点记录

## 结论

2026-09-06：停止扩展升级。2.0.1 固件记录 ID 15 已隔离，不能推送其他设备。

用户授权在实验室无人时任选继电器，先验证两种板型，成功后逐台更新并恢复各自升级前的开关状态；失败时通知用户手动恢复。实际只推送了以下两台，未向其他设备发送 OTA：

| 设备 | 板型 | 升级前 | 结果 |
| --- | --- | --- | --- |
| DDC10E / ID 39 | IoT-Relay | 1.8.10、关闭、0 条定时 | 上报 2.0.1；公司网络配置摘要确认；明确关闭指令确认；仍为关闭 |
| 0676B5 / ID 59，Staff Room 饮水机 | IoT-Outlet | 1.8.10、开启、14 条定时 | 上报 2.0.1 后持续重连；配置摘要未确认；单独恢复开启也超时；最后设备回报仍为关闭 |

这不是两种板型均通过，也不是全量升级完成。饮水机未恢复升级前的开启状态，需要现场恢复。没有为了测试而开启任何原本关闭的紫外灯。软件回报不代替实体触点或负载测量。

## 故障证据与限制

- 第二台在 OTA 后回报版本 2.0.1、协议模式 1、板型 IoT-Outlet、14 条定时、`control_inhibit=true`，配置摘要为空。
- 网络配置指令等待 90 秒超时；另一次明确恢复开启的指令同样等待 90 秒超时。此后没有继续发开启或 OTA 指令。
- 原生 MQTT 只读观察也收到相同状态，不是仅凭 Odoo 页面的旧记录得出结论。
- Broker 日志显示该设备从同一来源地址大约每 18 秒以同一 MQTT Client ID 重连，出现 `already connected, closing old connection`。这证明连接不稳定，但不能独立证明另一台设备冒用了身份，也不能仅凭日志区分掉电、崩溃与软件主动重连。
- DDC10E 的连接日志没有同样的连续重连现象。
- 预备的倒计时、重复指令和二次 OTA 测试没有执行，不能算通过。没有完成实体按钮、GPIO、断电恢复或电气测量。

## 固件与架构边界

构建版本 2.0.1，ESP8266 1MB/DOUT/64KB 文件系统布局；实际 Flash 为 4 MB 不构成更换映像布局的理由。

- 二进制 478240 字节；SHA-256：`c8bf72e14137d2c7bfa6c6e3b35a3812077cdd560fa2d3580a41ecb1a1bc2587`。
- PlatformIO 编译成功：RAM 34464/81920，Flash 474087/958448。
- 原生 C++ 协议守卫测试覆盖 25 项断言；这些测试不模拟 ESP8266 重连或 GPIO，不能推翻实体试点失败的结论。
- 只有旧版有效状态文件允许单向 V1 迁移模式。新设备保持严格 V2；接受有效的有序 V2 指令后保存模式 2，不再接受 V1 指令。
- V1 控制器仍会发送无序列、无到期时间的指令，一些旧指令没有 ID；迁移模式无法提供完整 V2 防重放保证。已有 ID 的旧指令仅在最近 16 项缓存内去重。
- 迁移专用 `restore_schedule` 只允许在 V1 模式下随关闭指令解除定时锁止，用于不先开启负载地恢复升级前定时安排；正常明确关闭仍保持锁止语义。
- 国家、公司 MQTT/OTA 路由与证书信任均不编译进固件。首次 pin 来自管理员拥有的本地公开证书，并逐字节校验公司 OTA 端点实际证书后下发。

生产 Odoo 仍为 19.0.1.0.19，生产桥接器、服务和数据库架构没有切换到 V2。V2 后端备份恢复、网关身份/公司归属修正及硬件验收门槛仍未完成。

## 恢复与再次验收

1. 先处理 Staff Room 饮水机 0676B5。现场确认设备与接线后，可先断电再上电，观察是否持续重连；不要据页面“在线”推断可正常控制。
2. 如需串口恢复，先与市电及负载完全断开，再由熟悉该板型的人使用合适的隔离低压工具。不得在带市电状态连接 USB 串口工具。
3. 已知旧生产固件 1.8.10 / ID 14 保留在受保护的生产附件中，没有隔离。不要使用已隔离的 1.8.9 / ID 13 或本次 2.0.1 / ID 15 进行批量恢复。旧固件可能含部署配置，不导出到 Git 或公开下载地址。
4. 需要收集启动原因、串口复位信息和供电/网络情况，确认故障原因后再构建修复版本；不能宣称现在已经修复。
5. 恢复后重新读取当前时间和定时任务，不机械重放旧的开启快照。饮水机原定 19:00 关闭，过了该时间不应为了匹配旧快照强行保持开启。
6. 两种板型分别通过 OTA、状态恢复、定时到期、重复指令、TLS 二次升级及重启测试后，才能重新讨论解除固件隔离和逐台扩展。离线的 ID 37、38 不在在线 OTA 范围内。

工具 `tools/relay_rolling_update.py` 每次只处理显式指定的一台设备，无全量循环或自动 OTA 重试。私有快照保留在服务器 `relay-rollout/device-{id}.json`；原始开关状态不会被后续失败覆盖。`restore_state` 的成功不代表网络配置或完整验收通过。
