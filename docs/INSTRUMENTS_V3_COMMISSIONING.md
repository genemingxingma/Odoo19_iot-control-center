## 原程序发现的问题

1. 早期错供的加热器源码已撤回，不能再作为实际 ESP8266 的接线依据。
2. 正确加热器源码的网络阻塞、故障记忆和温升保护需要增强；无液位传感器，不伪造液位读数。
3. 新版绑定单只 DS18B20 的 ROM 地址，断线、异常值和过期读数均禁止加热。
4. 洗脱仪使用阻塞等待，运行中难以及时处理停止；归零搜索结束未可靠区分到位与超时。
5. 原 SD 更新没有签名/目标板/内容校验，不适合直接连接远程控制平台。

## 架构与操作边界

- 本地状态机负责加热保护、定时注排液、归零和装片点动。用户设备为敞口模式，不伪造“门盖已关闭”信号；可选联锁模式仅用于实际安装了开关的机型。两款设备均不检测液位；Odoo 不参与实时闭环。
- Odoo 通过设备主动 HTTPS 轮询下发命令；令牌绑定唯一设备及公司，不自动创建或跨公司绑定。
- 温度目标和洗脱程序的下发不等于启动。加热由 SW2 本地启停，故障长按确认后仍需另行启用；洗脱需屏幕确认启动。
- 队列记录已排队、已发送、设备已应用、拒绝、超时和取消；不把“已发送”当作执行成功。
- 采样每分钟一次，按小时求平均；异常探头和时钟未同步记录保留诊断，但不进入温度统计。
- 离线事件先落盘，联网后补传。普通温度样本最多 128 条滚动缓存，覆盖数持久化并上报；报警和命令回执不覆盖。总事件目录上限为 192，洗脱运行前会清理可覆盖的普通样本并为本次关键运行日志预留容量；无法预留、关键日志耗尽或实际写入失败时保持安全停止。
- 实时状态与历史补传交替发送，避免旧启动周期的积压日志一直阻塞新命令。远程停止受网络/轮询延迟影响，不能替代本地急停。文件系统挂载失败不会自动格式化。
- 洗脱每次运行使用唯一运行号；程序发布后不可原地修改，复制为新版本；断电中断不会自动续跑。
- 屏幕 UI 与 ESP32 使用 V3 协议，不能将新版 ESP32 与旧版屏幕混刷。屏幕只负责显示/触摸；后续布局可随 ESP32 OTA 调整。
- 断网时可使用已经保存的程序，但首次网络接入需要正确 CA、设备令牌和时间同步。
- 当前屏幕是英文候选界面：运行总览、启动确认、暂停装片、维护、SD 更新确认；按用户要求，所有程序只在 Odoo 编辑，设备端不提供程序编辑。启动确认必须等确认页发送完成并稳定显示后才能接受，停止按钮不受该等待限制。

## 离线运行与保护逻辑

洗脱仪空闲时接收平台完整程序目录，校验身份、版本、数量和每个步骤后再原子替换本地目录，保存成功才回复已应用。断网、同步失败或重启后继续保留原有本地目录，可从屏幕选择并确认启动；断电中断的运行不会自动续跑。设备最多接受 64 个有效程序，超过资源上限会整批拒绝而不会截断。注液量依赖进液泵开启时间，排液依赖排液泵开启时间，必须现场标定，不把时间换算冒充体积实测。取消原程序注液后额外 5 秒 C 路排液，保留注液前定位和注液后的回位。液温只显示和写入步骤/异常日志；探头断线显示警告、记录恢复事件，但不停止定时程序。

### 电机基准（3.4.0-rc5）

用户最新确认全部采用原程序输出值，撤销此前暂定的注液溢水 60%、甩干排液 50%、初始化排液 80% 等比例。基准集中于 `firmware/instruments/lib/InstrumentCore/src/motor_profile.hpp`，来源为原压缩包 `2.0.2.0/public_var.h` 和 `2.0.2.0.ino`。只恢复输出/速度参数，不恢复原来的阻塞控制、液位假设或额外流程。

| 阶段 | 进液泵 | 排水口泵 | 溢水口泵 |
| --- | --- | --- | --- |
| A / B 注液计时期间 | 仅对应泵全开 | 关闭 | 全输出（255/255） |
| 注液前定位 / 注液后回位 | 关闭 | 关闭 | 关闭 |
| 等待人工 / 装片定位 / 洗脱 | 关闭 | 关闭 | 关闭 |
| 程序排液步骤 | 关闭 | 150/255，约 58.8% | 150/255，约 58.8% |
| 甩干 | 关闭 | 50/255，约 19.6% | 50/255，约 19.6% |
| 停止 / 故障 / 待机 | 关闭 | 关闭 | 关闭 |

两台泵仍使用独立驱动，不把电机直接并联。原值 50 是 8 位 PWM 数值，不是 50% 或 50V；占空比不保证等比例流量或等比例实测电压。低输出启动能力、溢水口流量和实际接管位置必须验证。

主轴由 STEP/DIR 控制，固件不能调节其供电电压。原基准为每转 3200 脉冲；归零、定位和洗脱 1 转/秒，甩干 10 转/秒，加速度均为 1 转/秒平方。平台新建洗脱步骤默认 1 转/秒、甩干步骤默认 10 转/秒，仍可按程序修改；已发布程序和明确指定的速度不会被静默覆盖。装片定位必须单独校准后启用，原参考速度为 3200 脉冲/秒；不是对敞口实机安全性的保证。

### 暂停装片

等待步骤不自动继续，也不因其旧 `duration_s` 值到期而继续或终止。仅活动步骤计入总运行超时。Odoo 隐藏等待行的时长；协议字段暂为兼容保留。屏幕六个槽位按三组对侧位置排列，仅用于位置指示，不能任意点选跳位。点击一次 `NEXT +180` 或 `NEXT +60`，完成一次定角度移动；不再需要按住、不受旧版 1 秒点动限制。移动中拒绝新定位请求及“继续”，不排队执行连点。到位后仍保持等待，需单独按 `CONTINUE` 才恢复程序。按 `STOP` 中止整个运行。

从初始槽位起，固定同方向按 `1 -> 4 -> 5 -> 2 -> 3 -> 6 -> 1` 切换，角度为 `0 -> 180 -> 240 -> 60 -> 120 -> 300 -> 0`；每次相对转角交替为 `+180、+60`，六次切换累计两圈回到初始位。若暂停时不在初始位，先显式点击 `ALIGN START` 对齐 1 号位，不在进入暂停时自动转动。只有电机停止且脉冲位置等于目标时才推进装片顺序；超时/中断不记为到位。界面不能检测是否已放入芯片，也不能验证质量平衡；必须确认实际停稳后装片，在继续前人工核对配平。

六槽按 60 度等分，用绝对目标取整而非每次累加 533 步，避免 3200/6 的舍入误差累积。仅首次对齐采用较短方向，之后的装片顺序固定正方向。装片零位与归零偏移分开标定。位置由归零后的脉冲数推算，不是编码器实测；手动扭转、堵转或丢步会破坏定位，必须停止并重新归零。未归零或未标定时定位不可用。

敞口设备的软件不能检测手部、衣物或异物，也没有门盖保护。单次点击触发完整角度移动，松手不会停止，必须先将手移出转子区域；软件停止不等于机械立即静止。实际延迟、惯性、触摸可靠性及硬件急停/防护必须在空载验证后验收。开机归零后排液 20 秒（输出按原值 150/255）、多程序目录及按循环数编程均已实现；仍须在空载机械测试中确认方向、速度、停止距离和实际流量。

加热器只接受平台设定，本地没有调温菜单。单路目标温度及温升保护原子保存到 `/targets.json`，离线和重启后使用同一配置；缺失、损坏或不完整配置时不能启用加热。默认保护值为 `rise_window_s=600`、`minimum_rise_c=1`，判断使用 `温升 < 阈值`。修改保护参数前须停止加热，修改目标温度不清除观察时间或解除报警。

温升观察累计实际输出开启时间；HTTPS 通信期间主动关闭加热，不计入这 600 秒，也不清零累计时间。未到目标温度时，每个窗口须升高至少 1 C；达到目标温度后重置窗口。探头断线、无效读数、读数过期、超温或温升不足均停机。温升不足不能证明一定缺液，还需检查探头位置、加热器、电源及液量。

报警保存到本地，恢复读数、下发新温度或重启不会自行恢复加热；必须在设备旁检查后长按确认。温度保护报警立即进入独立事件队列，联网后补传到平台“加热器报警”，不混入每分钟温度采样，避免改变小时均值。报警显示、蜂鸣器输出及断电记忆须实机验收。无论采用何种软件温升判断，都不能替代独立过温断电保护。

## 预定接线：必须现场核对

### 当前加热器源码映射（须实物核验）

| 功能 | ESP8266 候选引脚 |
| --- | --- |
| 单路加热 | GPIO16，高电平开启 |
| DS18B20 总线 | GPIO14，独立供电三线连接，单只探头按 ROM 地址绑定 |
| I2C SDA / SCL | GPIO4 / GPIO5 |
| SW1 / SW2 / SW3 | GPIO0 / GPIO2 / GPIO12，低有效；显示芯片/IP、启停、显示已保存设定 |
| OLED | SSD1306，I2C 地址 0x3C，128x64 |
| 蜂鸣器 | GPIO13，高有效 |

不增加液位传感器或 I/O 扩展板。SW2 运行中按下即请求停止，故障时长按 1.5 秒确认且不会自行恢复加热。上电或复位时不要按住 GPIO0/GPIO2 按钮，避免影响启动模式。

保留独立温控保护/温度保险丝；高有效驱动须保证上电默认关闭，偏置方式按实物核对。GPIO 不直接驱动负载，输入禁止接 5V。

### 洗脱仪

沿用原代码：使能 GPIO12（高有效）、STEP13、DIR15、HOME4、A泵33、B泵25、排水泵27、溢水泵26、温度32、蜂鸣器21；串口 RX16/TX17；SD 使用 VSPI18/19/23、CS5。27/26 与实物排水口/溢水口的映射根据原程序注液时单开 C 路推断，必须空载核对，不能当作已确认的接线图。

用户实机没有门盖开关，不要求将 GPIO34 短接来伪装闭盖。可选的联锁机型使用 GPIO34，外部上拉至 3.3V，闭合触点接地；GPIO34 没有内部上拉。敞口模式明确上报 `rotor_mode=open`，不发送 `door_closed=true`。软件停止不代表转子立即静止，应有独立硬件急停和适合该机构的防护。

## 首次配置与升级

配置保存在设备 LittleFS 中，不写死在源码；每台设备分别注册。

- `/hardware.json`：`commissioned` 默认 false；核验引脚/极性/保护后才可启用。加热器须绑定单只探头 ROM、确认三线供电和 4MB Flash；洗脱仪须 `home_offset_steps`。敞口实机须显式 `rotor_mode="open"`、`open_rotor_commissioned=true`；实际联锁机型可用 `door_interlock=true`，不默认绕过联锁。
- 已授权洗脱仪现场测试使用 `field_test=true` 与明确的敞口测试确认字段，仍保留 `commissioned=false`。不会自动归零；本地初始化确认后才允许动作，STOP 和重启撤销本次许可。暂停装片时可在确认当前槽位正确后用 `SET SLOT 1` 保存定位零位，不能凭软件测试自动生成“已标定”状态。
- 洗脱装片定位还需 `loading_calibrated=true`、`loading_offset_steps`（0..3199）和 `loading_index_hz`（32..3200 脉冲/秒，原基准为 3200）。缺少新字段时禁用，不沿用旧 `loading_jog_hz` 配置来自动启用更长角度或更高速度的运动。标定参数属于硬件配置，不是设备端程序编辑；须现场校准。
- 加热器硬件标识 `heater-esp12s-ds18b20-v1`，版本 `3.2.0-rc2` / `32001`，控制接口 `heater-control-v1`；旧双路与 PCF8574 标识均拒绝，远程启动始终拒绝。洗脱仪为 `3.4.0-rc5` / `30403`，均未完成负载实机验收。
- `/network.json`：`url`（HTTPS 服务根地址）、`uid`、随机 `token`、`ssid`、`password`、可选 `ntp`。不得将真实文件提交 Git。
- `/server-ca.pem`：验证服务器证书的 CA。禁止跳过 TLS 校验。
- `/ota-public.pem`：RSA-2048 升级验签公钥，只能从受控的首次配置流程写入。签名私钥离线保管，不放在设备或仓库中。
- 所有时间按 UTC 上报；公司/用户语言和时区在 Odoo 中处理，不在固件写死国家。

ESP32 分区：NVS + otadata + 两个各 0x1B0000 的 OTA 应用槽 + 0x90000 LittleFS；不启用 PSRAM。双槽不等于已验证的自动回滚，当前未声称支持启动失败自动回滚。

发布工具 `tools/package_instrument_firmware.py` 从固件内嵌标记读取设备类型、硬件版本与数值版本，生成签名清单和二进制。设备检查签名、硬件、大小、SHA-256，并拒绝相同或更低数值版本。

SD 更新只使用连接 ESP32 的 SD 卡，不是屏幕插槽。文件放入 `/imytest-update/manifest.json` 与 `/imytest-update/firmware.bin`。需空闲时从维护页确认，不能插卡即自动更新；不删除失败包，不修改屏幕固件。

首次从旧版固件切换必须 USB 有线配置并同时更新 HMI。OTA 只能在已安装新版升级逻辑后使用。

## 必须完成的实机验收

1. 断开加热负载和泵，核对每个输出上电/复位默认关闭及全部输入极性。
2. 使用无负载模拟/校准温度源验证 600 秒温升为 0、恰好 1 C、超过 1 C、恒温、探头断线/85 C/-127 C、异常温度和网络超时；确认单路加热实际断电，恰好 1 C 不触发温升不足。不做真实干烧试验。
3. 用空载转子验证归零方向、开关断线/常闭故障、133 步进液位置、回零偏移与转速/加速度。
4. 验证各步骤中本地停止、远程停止、屏幕断线与掉电；若装有联锁另测开盖。逐槽测试单击完整定位、180/60 交替、连点不排队、定位中按继续被拒绝、停止和超时不跳位；记录实际停止延迟和转子停稳时间。
5. 一次完整程序验证实际泵量、液温、排液与交替洗液；分别核对 A/B 注液时进液泵与溢水泵全输出且底部排液泵关闭，暂停时全部泵关闭，排液时两只排液泵均为 150/255，甩干时两只排液泵均为 50/255。平台循环次数已编译为正转、反转各一次的完整循环，仍须实机核对方向、转速与次数。
6. 真机分别验证 OTA、SD、错误签名、错误机型、旧版本、断网和断电恢复；测量 ESP8266 TLS 峰值堆内存及文件系统耐久性。
